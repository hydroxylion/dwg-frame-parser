# dwg-frame-parser（DWG/DXF 图框解析工具）

> 技术栈：Flask + ezdxf + 原生 JS（前端）

上传 DXF/DWG 图纸，后端智能识别图框并返回宽×高（mm）、图框数量及候选明细。

## 一、图框识别算法（核心流程）

### 1. 候选收集（模型空间 + 所有布局空间）

| 候选来源 | 说明 |
| --- | --- |
| 闭合多段线 | LWPOLYLINE/POLYLINE，含矩形度过滤（≥0.92，剔除 L 形标题栏等） |
| INSERT 块参照 | 块定义 bbox × xscale/yscale + rotation + insert 点 = 真实图框 bbox；预筛短边 ≥500mm（**或命中标准 A 系列短边 210/297/420…**，A4 等小块图框块可入库；**或命中"布局空间网格排版图框"救援**，见下）且长宽比 ∈[1.05, 5.5] |
| 直线矩形 | 共线聚合 + 线对配对 + P1 严格矩形判定（4 边各有完整 LINE 覆盖；**R140 起**：单条完整线不成立时，若该矩形占版面 ≥10%，允许用**同一坐标上首尾精确相接的多段 LINE**拼成边——CAXA 导出常把页框上下边画断成 2~3 段，断口零缝隙，几何上就是"一条被画断的线"）；**R142 起**：短边下限 `MIN_LINE_RECT_SIDE` 100→**70**、长边全配门槛 `LINE_PAIR_FULL_SPAN` 180→**70**，两者统一为「一条线至少要有一个短边的长度，才可能充当某条边」——小页框的**竖边长度恰好等于框高**（A6 的 74.25），180 口径下进不了长配通道，而密集机械图里它与对边隔着 13~48 个竖线聚类，相邻配对也够不到 → 竖对永远配不上（报障图 7 个框全部漏在此处）；**R141 起**：四角相接给 3mm 松弛量 `P1_CORNER_SLACK`，只用于"这条边有没有延伸到与邻边相交的那个角"，共线判定仍是 0.5mm——报障图 5 个框的左下角横/竖各短 2mm，0.5mm 口径判"没接上"→ 整框不成立）；密集聚类时**长边（跨度≥70，R142 起；原 180）全配对**找回远距离图框边界，线对按公共覆盖长度排序；组合扫描按**竖对 x 起点落在横线公共覆盖段内（xa∈[xLo,xHi] 且 xb≤xHi）、xa 升序**遍历——帧左边界对排最前命中即确认，坐标直接排除大量无效竖对，杜绝高密度图（数万线对）预算耗尽漏检 |
| 全实体包围盒（降级） | 以上全无时兜底；**排除 VIEWPORT 与文字/标注类实体**（TEXT/MTEXT/DIMENSION 等——文字允许外溢，不撑宽图框） |

**坐标处理**：
- 实体坐标统一 **OCS→WCS** 转换（`get_polyline_vertices`/LINE 端点经 `ocs().to_wcs()`），兼容带倾斜 extrusion 的实体
- **全局旋转矫正**：自定义 UCS 整体倾斜的图纸（实体坐标斜存 WCS），按长度加权直方图估计主方向，主体共旋占比 ≥65% 才施加旋转矩阵"转正"（防混合方向图纸误转），使矩形度 / 水平垂直检测恢复有效

**可见性过滤**（收集前）：跳过冻结/隐藏图层实体 + 实体级 invisible（组码 60），只统计 CAD 里可见的实体。

**布局空间「网格排版图框」救援**（INSERT 预筛的补充通道，2026-09-11 修法A）：仅对**图纸空间布局**生效（模型空间不做救援）。判据 = 同块名同尺寸（宽高各 ±2mm）INSERT **≥4 个** + 长宽比 ∈ 图框区间 + **排列成网格**（按 X/Y 一维聚类得列数 ≥2、行数 ≥2，网格覆盖率 ≥80%）。命中即豁免这些实例的短边下限，使其进入候选库（是否算图框仍由 `is_frame_like` 决定）。动机：布局空间本就是排图纸页的地方，出现多个等大框是"一版多页"的强信号，与绝对尺寸无关。典型：DS4 四层阁楼平面系统图 —— 6 个 A4 页面框按 1.0475 倍画在布局空间（434.1×311.1，短边 311.1 <500 且不在 A 系列），原本被预筛整体剔除。开关：`FRAME_PARSER_NO_GRID_RESCUE=1`。

### 2. 图框特征匹配（is_frame_like，按序判定）

- **前置**：归一化长宽比 ∈ [1.05, 5.5]；`area_ratio > 1.0 + 0.1%`（候选面积超过 layout 总面积，含浮点容差）直接判异常剔除
- **条件 A**：面积占比 ≥ 15%（常规单图框 layout）
- **条件 C**：相对面积 ≥ 该 layout 最大候选面积 × 10% **且长宽比 ≤ 2.5**（上限剔除细长内容块 bbox 冒充图框）；长宽比下限按类型分流——**直线矩形放宽到 1.10**（P1 严格矩形，四边各有完整 LINE 覆盖，是刻意画的框，几乎无"内容轮廓冒充"风险；非等比拉伸的大页面框 ratio 1.17 也放行），**闭合多段线 / INSERT 块 / 降级包围盒维持 √2×0.95≈1.343**（近方形内容外框 1.06/1.21/1.24 仍被挡）。**rel 分母排除内容级底图大框（两条判据互补）**：① 面积占比 ≥50% 且长宽比偏离 √2 超 10%（排版大外框包住全部页面会稀释真页框 rel）；② 面积占比 ≥15% 且长宽比 >2.5（超宽内容条带/排版外框，底框外大量内容拉大 layout 总面积时逃过 ①）。这类大框最终由包裹剔除收掉，真整页图框即使占 100% 也近 √2 且 ratio ≤2.5，两条判据都不命中，不受影响
- **条件 B**：显式矩形 + 短边 ∈[400, 2000]mm + 宽高接近整数 + 长宽比接近 √2±10% **+ 相对面积 ≥10%**（密集几何场景，过滤家具/设备小矩形与 CAD 远处/主框区外的孤立小矩形；直线矩形与闭合多段线统一要求）
- **rel 分母塌缩防护**（在 rel 计算前统一判定）：若某 layout 的 rel 分母（最大候选面积）**占该 layout 总面积 < 1%**，**且**存在**占 layout 面积 ≥50% 的被排除大框**，则判定为**「整图即图框、内无图框级参照系」**（典型：1:1 设备布置图/总图，整图外轮廓因长宽比偏离 √2 被排除，分母塌缩到图内某个设备构件，导致所有构件 rel 虚高数十倍而误入条件 C）——该空间所有候选的 `rel_area_ratio` 一律置 **0**，只保留条件 A（占比 ≥15%）与条件 B 通道。开关：环境变量 `FRAME_PARSER_NO_DENOM_GUARD=1` 可关闭（仅回归对照用）
- **条件 D**：同 layout **同尺寸直线矩形 ≥2 份** + 长宽比接近 **√2±2%** + 短边 ≥500 + 相对面积 ≥1% + 框内严格内部实体 ≥12（多尺度"套图"里小页框面积远小于最大图框仍可识别；rel≥1% 排除重复表格/阵列矩形）。**√2 容差 R138 由 ±10% 收紧到 ±2%**：条件D 判的是"同一页框模板重复排版"，重复出来的尺寸一模一样、比例必然精确到纸幅级（84100/59400 偏差 0.11%、电子称 14894×10531 偏差 0.01%），±10% 是 `_near_sqrt2` 从条件B 继承来的宽口径，从未为 D 论证过。动机（`DTⅡ型固定式带式输送机.dwg` 识 2 实际 0）：该图模型空间根本没有图框（A0@1:100 的外框 118900×84100 左边/上边/下边三条边都精确，**唯独右边那条竖线被画到了 x=1474645**，比正确位置 1457448 偏出 17197mm，框永远闭不上），两个 4000×2655 是同一台皮带机两侧滚筒的对称半区（左右竖边是 `中心` 层中心线、上下边是侧板轮廓），ratio 1.5066 与 √2 差 6.50%，只靠旧口径 ±10% 擦线通过。开关：`FRAME_PARSER_COND_D_RATIO_TOL`（数值，仅回归对照用）
- **条件 E（块模板标准幅面 / A+ 通道）**：**块参照**的块定义本身是标准图幅（短边 ∈ {841,594,420,297,210,148,105} 且长边 ≈ 短边×√2，容差 1mm）+ 实例尺寸 / 块定义尺寸 = k 为**等比**（宽高比值一致，兼容 rotation 90° 宽高互换）+ k 落在 `COMMON_PLOT_SCALES` 常用制图比例白名单（1/2/2.5/4/5/10/15/20/25/40/50/75/80/100/150/200/250/300/400/500）→ 放行。判据**不依赖面积占比与绝对尺寸**，只看"模板是标准图幅 + 倍率合法"，解决同一标准图幅块被以多种比例重复插入（尺寸跨度大）时的漏检；家具/门窗符号块定义不在 A 系列、自定义倍率（39.05× 等）被白名单拦下
- **同块名族"一荣俱荣"传播**：按块名分组，族内只要有 ≥1 个实例通过既有判定（A/B/C/D/E）→ 整族一并放行；约束**族内所有实例长宽比均接近 √2（±10%）**，任一实例比例异常即整族放弃传播（装饰块阵列比例远离 √2，不会被连带放行）。覆盖自定义尺寸图框块（块定义非 A 系列，但族内大尺寸实例已靠条件 A/C 通过）——"这个块是图框"是整体事实，同一块画了 N 次没有理由只有最大的那张算图框
- **R136 块定义结构签名族传播**：族键从「块名」换成「**块定义的实体结构签名**」（实体类型 → 数量元组）。同一签名族内**已有 ≥1 个实例通过既有判定**（种子）、且族内含 ≥2 个**不同块定义**时，其余实例一并放行；约束 ① 族内**所有**候选实例长宽比均接近 √2（±10%）② 目标块定义内**递归有文字**（图框必有标题栏/图名/图号，纯几何包装块不算）③ 目标 rel ≥ 0.3%（挡碰巧同签名的零星碎块）→ 任一不满足即整族放弃。与同块名族传播的分工：那条管「一个块定义被插入 N 次」，本条管「一个模板被**复制成 N 个块定义**再各自 1:1 插入」——块名互不相同、块定义尺寸就等于最终图框尺寸，同块名族传播对它完全失效。动机（`输送线出图6.01.dwg` 识 4 实际 5）：`2520×1782`（= A3 短边 297×**6**）逐条判死——A `area_ratio` 0.05% / C `rel` 0.37% / B 块参照非 `EXPLICIT_TYPES` / E 只差「6 不在 `COMMON_PLOT_SCALES`」。**不再往白名单塞数字**：本图 5 个框的倍率谱系是 35/20/20/10/6，35 与 6 都不在白名单（35 只因面积最大靠条件A 侥幸过关），上一轮 R135 缺 15、本轮缺 6 —— 连续两张漏在同一处，说明「出图比例白名单」对不按标准比例排版的图（皮带输送机/非标设备出图）本质上不成立，故改用与倍率无关的结构判据。实测该图签名 `(LINE 62, LWPOLYLINE 23, MTEXT 34)` 全图恰好 2 块（种子 41615×29435 + 目标 2520×1782），零多余命中。开关：`FRAME_PARSER_NO_STRUCT_FAMILY=1`
- **R137 旧式二维多段线（heavy POLYLINE）全链路补齐**：图框画成 DXF 的 `POLYLINE`（不是 `LWPOLYLINE`）时，块内的图框此前**完全看不见**——app.py 里有四处「内联类型分派」只写了 `'LWPOLYLINE'`，`POLYLINE` 整类被静默跳过：① `block_world_bbox` 返回 `None`（实例连预筛都没进）② `_block_max_member_len` 最长直边构件恒 0（被 R26 判「闭合框疑为碎线拼成」剔除）③ `_closed_polyline_rect_len` 矩形证据恒 0 ④ `_block_closed_frame_len` 闭合边框证据恒 0。四处叠加后真框从头到尾不在候选池里，程序只能拿图内两张表格的相邻小格（1750×3300）顶数。**顶层直接画的闭合 `POLYLINE` 一直是认的**（候选收集写的是 `dxftype in ('LWPOLYLINE','POLYLINE')`），缺口只在**块内**三条证据链。动机（`JQCG300-26侧式刮板取料机.dwg` 识 2 实际 1，真框 59450×42050）：真框是块 `*U123`，块定义里**只有 2 条闭合 POLYLINE**（1189×841 外框 = A0、1149×801 内框，均 4 顶点矩形），按 1:50 插入即 59450×42050，与该图 `$EXTMIN/$EXTMAX` 精确吻合。修法是把四处分派补齐（`POLYLINE` 取 `vertices` 的 OCS 坐标，`LWPOLYLINE` 原有 `get_points` 口径一字未动），**不放宽任何判据**：矩形度检查（面积比 ≥0.92 / 4 顶点斜放矩形）对 `POLYLINE` 同样生效，L 形闭合多段线大块照样被拒
- **条件 H（主导比例内容救援，2026-09-14）**：未入选的**闭合多段线/直线矩形**候选若同时满足 ① 长宽比与同 layout 内 **≥3 个已入选图框共享的主导比例一致（聚类与匹配均取 ±0.5%）**——同模板缩放出图比例是指纹，模板拷贝精确到 1e-6 量级，0.5% 已足够宽松；取 0.5% 而非 1% 是防"近邻比例混簇"（新古典式 21728×15365 ratio 1.4141 与其内框 21302×14939 ratio 1.4259 相差 0.83%，±1% 下会合并成伪主导簇导致家具详图边框 3900×2720 被误救；±0.5% 下两簇各自凑不满 3 → 该图 H 自动失效）② bbox 内**完全包含 ≥12 个实体**（真页面框内必有大量图纸内容，实测 52~839；比例恰好落在主导比例附近的窗户 decoy 1277×882 ratio 1.4478 框内只有自身边线，实测 5~6 个，被内容数干净排除）③ 已被某个"已入选"图框完全包住的候选不救（嵌套去重反正会剔，救入只是噪音——1280×1850 虚线窗套实证）④ **框内须含「文字/标注/块参照」之一**（`TEXT`/`MTEXT`/`DIMENSION`/`INSERT`，**R142 起**）——图框是**出图页**，页内必有图名、图号、说明、标注，或整块的内容参照；**纯几何轮廓不构成页面**（`2.8米皮带线.DWG` 的 113×80 管子端面：ARC 15 / CIRCLE 8 / LWPOLYLINE 2 / LINE 6，零文字零标注，比例 1.4125 却恰好落在主导 √2 簇 ±0.5% 内、框内 31 实体 ≥12，①②两条信号全中）。闸门不放尺寸下限：`美立方-说明.dwg` 靠 H 救入 12 个 630×446 / 585×431（短边仅 431），任何尺寸门槛都会误伤 → 救援放行。动机：春风公寓２ 的 21 个图框是同模板四种比例排版（ratio 全部 = 1.4444），右侧 5 张小图框（17472×12096 / 14560×10080×3 / 10735×7432）标题栏只有一条全高分隔线、没有横向分隔线——条件 G 的条纹签名不命中，其余通道也全堵（rel 3.7~9.9% / area_ratio 0.1~0.4% / 短边 >2000 / 非直线矩形）。与条件 G 的分工：G 靠"标题栏条纹"结构签名，H 靠"比例指纹 + 框内内容量"，两签名互补覆盖标题栏画法不同的套图。开关：`FRAME_PARSER_NO_COND_H=1`（整条关闭）；**R142 起**另有 `FRAME_PARSER_COND_H_NO_TEXT_REQ=1` 可只关掉第 ④ 条「页面内容」判据

### 3. 候选清洗（匹配通过后）

1. **包裹框剔除**：内部完全包含 ≥2 个独立尺寸图框候选的大框判为外包络剔除（按 5% 尺寸聚类去重，避免同图框重复画法误剔；单尺寸组实例 ≥3 也判为拼版外框；跳过 INSERT 块参照；**自身长宽比接近 √2±10% 的显式矩形豁免**——纸张边框不是拼版外框，内部内容交由嵌套去重收掉）
2. **对齐排列剔除**：同块名 ≥3 个 INSERT 实例短方向紧贴成线判为装饰块（柱网/门窗阵列）；**白名单保护**（不参与剔除）：标准 A 系列整数尺寸（短边 ∈{841,594,420,297,210,148,105} 且长边 ≈ 短边×√2）**或长宽比接近 √2±10%** 的块——图框块（含自定义尺寸模板）多张并排时不误剔，装饰块比例远离 √2 不受影响
3. **去重**：嵌套（面积 < 外框 95%）+ IoU > 50%
4. **模型空间降级框清洗**：布局空间已识别真图框时，剔除模型空间的"全实体包围盒"（模型空间仅是内容区）
5. **布局空间优先**（2026-09-11 修法A）：若**布局空间**（非模型空间）已识别出 **≥4 个**图框且模型空间也有候选 → 剔除**模型空间的全部候选**。理由：布局空间是出图页面空间，一旦其中排出多个等大页面框，模型空间就只是这些页面的内容源，其内的任何大框都不是图框。与第 4 条同源，但更彻底（那条只清"全实体包围盒"）。开关：`FRAME_PARSER_NO_LAYOUT_WINS=1`
6. **每 layout 上限 100**（防爆炸兜底）

### 4. XREF 外部参照警告

ezdxf 默认不加载 XREF 外部文件，引用块会漏识别图框。检测到时写日志警告（不阻塞解析），API 返回 `xref_warnings` 字段供前端展示。

### 5. 输出

- `width` / `height`：选中图框尺寸（面积最大候选，可按优先级加权）
- `frame_count`：图框数量
- `frame_counts_by_layout`：按布局分组的图框数（如 `{"模型空间": 3, "布局 \"Sheet1\"": 2}`）
- `candidates`：候选明细（前 20）
- `xref_warnings`：XREF 警告列表

## 四、API

`POST /upload`（multipart/form-data）

| 参数 | 说明 |
| --- | --- |
| file | .dxf / .dwg 文件 |
| priority | polyline（默认）/ line_rect |

## 五、本地运行

```
pip install -r requirements.txt
python app.py
```

启动后访问 `http://127.0.0.1:5000`。`.dwg` 解析依赖 [ODA File Converter](https://www.opendesign.com/guestfiles/oda_file_converter)，需本机安装并保持默认路径；`.dxf` 可直接解析。

**端口配置与冲突防护**（2026-09-15）：

- 端口默认 5000，可用环境变量 `FLASK_PORT` 更改：`set FLASK_PORT=5001 && python app.py`；或直接双击 `start-dwg.bat`（固定 5001，与其他本地项目隔离）。
- 启动前有**端口占用预检**（`assert_port_free`）：端口被占即报错退出并给出排查命令，不再容忍 Windows 下同端口双进程静默绑定（Flask dev server SO_REUSEADDR 行为，曾致新旧两服务抢 5000、上传连接随机重置）。
- 排查命令：`netstat -ano | findstr :端口` → `tasklist | findstr PID` → `taskkill /F /PID PID`。

**回归与自测**：

```
python test_backend_rules.py      # 后端规则单测（358 项）
python regress_check.py           # 全量回归（按负载分档并行 + DXF 缓存）
python regress_check.py --skip-slowest 8  # 迭代阶段：跳过最慢 8 张（约 11 分钟）
python regress_check.py --skip-slowest 8 --keep a.dwg,b.dwg  # 强制保留某几张
python regress_check.py --serial  # 串行对照（排查用）
python regress_check.py --workers 2   # 手动压并行度上限（机器忙时用）
python regress_check.py --update  # 把当前结果写回基线（确认行为正确后使用）
python regress_check.py --update --prune   # 补录并删除「本次没跑到」的旧基线条目
python regress_check.py --files a.dwg,b.dwg # 冒烟：只跑指定图纸

npm install                       # 首次：装前端测试依赖 jsdom
npm test                          # 前端全部用例（8 个文件，273 项，汇总输出）
node test_judge_logic.js          # 也可单独跑某一个（其余 test_*.js 同理）
```

> 回归怎么分配并行度（R127）：先按**图纸体积折算的负载**分三档（≥8 / ≥3 / 其余 MB），
> 每档的并行度 = 可用内存×0.75 ÷ 档内最重那张的峰值（峰值 ≈ 负载 × 0.8GB），上限 8。
> 所以同一份图纸在不同机器/不同时刻跑，档位和路数可能不同——这是刻意的，因为
> **单 worker 解析大图的峰值实测能到 5GB**，写死并行度在内存紧张的机器上会 OOM。
>
> **迭代阶段怎么跑（R129）**：日常改规则用 `--skip-slowest 8`，跳过最慢的 8 张
> （占全量 33.2 分钟里的 20.3 分钟，实测降到 **10.9 分钟**）；排序依据是
> `regress_timings.json` 里的实测耗时（每轮回归自动累积、取历史最大值），不是体积代理。
> 跳过名单会逐条打印、汇总单独计数——**覆盖缩小必须可见**。改动收敛或发版前
> 必须跑一次不带该参数的全量；若本轮改动涉及那 8 张里的某张，用 `--keep` 留住它。

> `--update` 默认**不删除**「本次没跑到」的既有基线条目，只列出来提醒（这些多为
> 图纸改名后的残留，删掉就等于让那张图退出回归覆盖）；确认要清理时加 `--prune`。
> 解析报错也不会覆盖原本正常的条目 —— 否则基线会把 `error` 记成"预期结果"，之后
> 永远 SAME，覆盖同样静默消失。

## 六、日志

运行日志写入项目根目录 `parser.log`（UTF-8），采用**按大小轮转**（`RotatingFileHandler`）：

| 项 | 值 |
| --- | --- |
| 单文件上限 | 10MB（`LOG_MAX_BYTES`） |
| 历史文件数 | 4 份（`parser.log.1` ~ `.4`，`LOG_BACKUP_COUNT`） |
| 磁盘占用上限 | ≈ 50MB |
| 启动预归档 | `_archive_oversized_log()`：启动时若 `parser.log` 已超阈值，先归档为 `.1` 并把历史序号整体后移，保证新一轮运行从干净文件开始；文件被其它进程占用时静默跳过（不阻断启动），由轮转机制在写入时自行切分 |

排查用法：`parser.log` 是当前日志，`.1` 是上一轮；每次解析的关键节点都输出日志（候选收集统计、INSERT 预筛、包裹框剔除、去重剔除、`全部候选 / 通过特征 / 去重后 / 上限后` 汇总、选中结果），可直接按文件名或 `全部候选` 检索定位。
