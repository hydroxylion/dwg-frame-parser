## 逐轮记录（最新在前）

### 2026-10-23（第九十轮 —— 140822雅安综合艺术楼平面参照_t7 识 101 实际 4：R90 布局空间优先的「房间量级不豁免」）

**需求**：该图识别 101 张，用户口径**只有布局空间的 4 张是对的**，其余空间（模型空间）应为 0。

**现象拆解**：fc = 101 = 模型空间 97 + 布局"布局1" 4。布局那 4 张是 841×594 块参照插入，**识别完全正确**；问题全在模型空间 97 个。

**那 97 个是什么**：全是 `直线矩形`，绝对尺寸 1~10 米（79 个 5~10m + 18 个 1~5m），是**房间轮廓**——8100×5600×40、5400×8100×36、3450×8100×10、8100×5750×3、8100×4150×2、8100×3950×2…。8.1m×5.6m 就是真实房间（病房/办公），而它的比例恰好落在 √2 附近。

**根因：R52「布局空间优先」的两条豁免同时被房间轮廓占满**

R52 的本意是"布局已排好版 → 模型空间只是内容源 → 模型候选全部剔除"，但它留了两个豁免口子：

```python
_model_keep = [c for c in _model_cands
               if abs(c['ratio'] - √2) / √2 <= 0.02        # ① 比例≈√2
               or (c.get('rel_area_ratio', 0) >= 0.25        # ② rel≥25%
                   and len(_model_cands) >= 3
                   and not c.get('rescued_by'))]
```

房间轮廓把两条都占满：
- **① 比例**：8100/5600 = 1.4464（偏 2.28%）、5400/8100 = 1.5000（偏 6.07%）、8100/5750 = 1.4087（**仅偏 0.39%**）→ 全在 √2±2% 内；
- **② rel**：高达 **42%~71%**。

于是 97 个全部豁免，R52 只剔掉了 3 个。

**更深一层：rel 分母自我循环**（这是这类误报的通用机理，值得单独记）

模型空间的 rel 分母取该空间内**最大候选**，而最大候选**就是房间轮廓自己**（8100×5750）。所以每个房间 rel = 自身/最大房间 = 42%~71%，条件C 的 10% 门槛形同虚设。**分母与候选同类时，相对面积法彻底失去判别力**——条件C 隐含假设"分母是图框、候选是内容"（或反之），而当空间里压根没有图框时，分母自己就是内容。这正是 R52 这类"兜底规则"存在的意义，但它的豁免口子把兜底能力抵消了。

**另一道防线也没兜住**：R66 共边网格链剔除成功剔掉了 50 个分格阵列，但它有豁免①「分量内任一同尺寸组 ≥3 份 → 判为拼版页」，而 8100×5600 有 **40 份**同尺寸 → 直接豁免。

**修法（方案 A，用户选定）**：短边 < `ROOM_MAX_SIDE`(10000mm) 的候选视为**真实房间/构件尺寸**，不是"图纸坐标里的页面框"，一律不享受 R52 的任何豁免。开关 `FRAME_PARSER_NO_ROOM_SCALE=1` 回退。

**门槛怎么定的（先调研再动手）**：把全回归库 80 张图跑一遍，筛出"布局有真页 且 模型空间也有候选"的 14 张（这些才受 R52 影响），取各图模型候选短边最小值：

| 模型候选短边最小值 | 图纸 | 性质 |
| --- | --- | --- |
| **3450 ~ 5750** | 本图（97 个房间轮廓） | 该剔 |
| **14813** | 罗马都市gai222.dwg（基线 fc=2） | 真图框，该留 |
| **16820** | 大样图(内外保温).dwg（基线 fc=7） | 真图框，该留 |
| 29700 起 | 其余全部 | 真图框，该留 |

空隙在 **5750 与 14813 之间**，10000 落在中间，两侧余量 1.74× / 1.48×。物理依据：图纸坐标里 A1 是 84100×59400（短边 84m），真实房间是 8m 级；短边 <10m 的"框"要么是房间、要么是构件，不会是整页纸。

**验证**：目标图 **fc=101 → 4**，`by_layout = {'布局 "布局1"': 4}`，尺寸全 841×594，**模型空间清零**；单测 **149/149**（+用例 113 两条：房间量级 8100×5600 全剔 fc=4 / 对照真实图框量级 59400×42050 仍享 √2 豁免保留 fc=5——证明不是"布局有页就清空模型"的一刀切）；全量回归 **零 DIFF**，61 张基线全一致。

**方法论收获**：

### 2026-09-23（第二十八轮 —— 孤证复核证据评分制试点：六通道布尔逻辑 → 加权评分（等价重构，行为逐位不变））

**背景**：架构评审确认项目存在 3 个结构性风险（阈值逐案拍定、顺序承载正确性、隐式假设累积），其中"条件逐案加 if 分支"的演进方式在 R27 回归期间暴露得最充分——互证资格限制（area_ratio/尺寸/类型下限）两次被全量插桩数据证伪（32 张基线 413 条救援样本证明尘埃与真框在单维特征上不可分：420mm 的 A3 真框 < 尘埃 957mm；滨江 11093×8535×15 弱+弱真框副本对 vs 一层.dwg 960×2400 门副本）。结论：未来新案例的正确演进路径是"调权重 / 加特征"，而不是"加 if 分支"。

**修法**（app.py 孤证复核段等价重构，作为评分制的第一个试点段）：
- 六通道互证布尔逻辑（原 `_corr` 标志 + 任一命中即救援）改写为加权评分：**score = Σ wᵢ·fᵢ**（fᵢ∈{0,1}），`score < _SOLO_SCORE_THRESHOLD(0.5)` → 孤证剔除。六通道对应 6 个权重键，集中于 `_SOLO_WEIGHTS` 表：①`same_size_copy`（同 layout 同尺寸副本）②`same_ratio_sibling`（同比例兄弟 ±1%）③`title_stripe`（自带标题栏条纹）④`stripe_inside`（内含带条纹子候选）⑤`name_declared`（块名含 图框/frame）⑥`nested_frame`（内含不同尺寸通过候选）。
- 评分收敛为纯函数 `_solo_evidence_score(_c)`，返回 `(score, hits)`——hits 为命中证据明细，供调试日志输出。
- 新增开关 `FRAME_PARSER_SOLO_DEBUG=1`：保留分支逐候选输出 `[孤证评分] WxH 保留 score=…（证据明细）`，替代原先"只知结果不知理由"的黑盒状态。
- 触发条件（`_via=='C' && area_ratio<0.05`）、剔除汇总日志、历史场景注释全部保留原样。

**等价性论证**（行为逐位不变的依据）：
- 初始权重全部 1.0、阈值 0.5 → `score > 0 ⟺ 原 _corr=True`：任一证据命中即过阈值，与"任一互证即救、无互证则剔"一致。
- 原布尔逻辑的短路语义（命中即停）与求和语义在正权重下等价：多证据叠加只增大分值，不改变保留结论；①②⑥ 各自命中后 break 保留（省时且语义不变），④ 改为无条件检查只增分值不改结论。
- 唯一结构差异是求值方式（标志位 → 累加分），不涉及任何候选增删顺序变化。

**验证**：后端 **56/56**（含孤证复核直接消费者用例 41/42/43/48，用例 48"同尺寸副本对经互证①保留"正路径保持）；**33 张基线回归全部 SAME（零 DIFF 零 NEW）**——等价重构的硬验收。附 `FRAME_PARSER_SOLO_DEBUG=1` 冒烟（地下室电力t3，5m47s）：51 条评分日志，score 与命中证据一目了然（如 `118900x84100 保留 score=5.0（①同尺寸 直线矩形；②同比例…；③标题栏条纹；④内含条纹子…；⑥内含…）`），73600×57400×11 真框副本对经①②救援路径清晰可读，fc=32 与基线一致。

**评分制演进路径**（后续轮次按数据决定是否推广）：

- 权重分级调优只改 `_SOLO_WEIGHTS` 表，不动逻辑代码：如 ③④⑤ 定为强证据（权重 ≥ 阈值，单独成立即救）、①②⑥ 依伙伴类型/副本数细分权重——每次调整用 33 张基线回归验证。

### 2026-09-14（第十轮 —— 两处修复：INSERT 旋转度/弧度混用 + 候选明细截断）

**修复 1：INSERT 旋转角单位错误（胜利公寓２"马桶块 bbox 错位"遗留 bug）**

- **现象**：`马桶` 块 INSERT 候选 bbox 算到 (419856,-1098934)、尺寸 900×850，真实为 (618129,-60412)、500×750。

  2. 布局空间网格救援路径：同上；
  3. `_get_block_world_bbox` 嵌套 INSERT 组合：补上子块旋转（度→弧度）与子块基点。

**同日补充（第三轮）—— Excel 导出列宽自适应**：

- **背景**：原「导出」实际是 CSV，而 CSV 格式**根本不存储列宽**，Excel 打开只能套默认宽度（8.43 字符），无法自适应；导出表里「图纸名称」经常被压得看不见

- **样式必须用支持写样式的库**：免费版 SheetJS（`xlsx.full.min.js`）**不支持写单元格样式**，`cell.s` 会被**静默丢弃**——实测导出的 zip 里 `s=` 属性根本没写入、`styles.xml` 里也搜不到 `wrapText`。后果是含 `\n` 的多行文本（图框尺寸、布局分布）在 Excel 里**被挤成一行显示**，视觉上就像"列宽没自适应"。换 `xlsx-js-style` 后 `cell.s` 才真正落盘：表头加粗 + 浅灰底（`F0F3F8`）+ 居中、数据 `vertical:'top'` + `wrapText:true`、冻结表头行（`!freeze`）
- **MIME 坑**：SheetJS 的 `XLSX.writeFile` 在浏览器分支把 Blob 的 type **写死成 `application/octet-stream`**，传 `mimeType` 参数无效（读源码确认）。改为自己 `XLSX.write({bookType:'xlsx', type:'array'})` 取字节 + 造标准 MIME 的 Blob 下载，并延时 `revokeObjectURL` 释放
